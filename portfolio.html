Mobile app · JavaScript

Project Title: CampusConnect

Student timetable & study planner

Software Used

JavaScript (ES6+)React NativeExpoFirebase Auth & FirestoreFigmaVS CodeGit & GitHubAndroid Studio emulator

Project Overview

CampusConnect is a cross-platform mobile app that brings a student’s timetable, assignment deadlines and study sessions into one simple place. It tackles a common problem: lectures, due dates and study time end up scattered across notes, chat groups and calendars.

Design Process

  1. Discover. Defined the problem and wrote user stories such as “As a student, I want a reminder the day before a deadline.”
  2. Design. Sketched screens on paper, then built clickable wireframes in Figma with a clear, low-clutter layout and bottom-tab navigation.
  3. Build. Developed the app with JavaScript and React Native (Expo), using Firebase Authentication for sign-in, Firestore for data and scheduled notifications for reminders.
  4. Test & refine. Ran the app on an Android emulator and a physical phone, fixed date-handling and navigation bugs, and simplified the add-task flow.

Final Outcome

A working, Android-ready prototype that lets a student plan their week at a glance.

  • Secure sign-in and a personal weekly timetable
  • Deadline tracker with automatic reminders
  • Study-session timer to support focused revision
  • Consistent, easy-to-scan interface across every screen

AI Usage Disclosure

I used Claude (an AI assistant) to brainstorm the initial feature list and to help me understand error messages while debugging Firestore queries. All screen designs, the final code and the testing were done by me.

02

Web app · Python

Project Title: SpazaStock

Inventory & sales tracker for small shops

Software Used

Python 3FlaskSQLAlchemySQLitePandasChart.jsHTML5 & CSS3BootstrapVS CodeGit & GitHub

Project Overview

SpazaStock is a lightweight web application that helps small retailers record stock, log daily sales and see what needs re-ordering. It is designed to load quickly in a phone browser and to be simple enough to use without any training.

Design Process

  1. Discover. Listed the everyday tasks of a small shop: receiving stock, recording sales and spotting items that are running low.
  2. Design. Drew an entity-relationship diagram (products, sales, suppliers) and sketched a dashboard wireframe focused on what the owner needs first.
  3. Build. Built the back-end with Python, Flask, SQLAlchemy and SQLite; styled the interface with Bootstrap; added Chart.js graphs and a Pandas-powered CSV export.
  4. Test & refine. Tested with sample data and edge cases, such as selling more than is in stock, and improved the validation and error messages.

Final Outcome

A responsive dashboard that turns raw sales records into clear, actionable information.

  • Dashboard with today’s sales and a weekly sales chart
  • Low-stock alerts to guide re-ordering
  • Product management: add, edit and remove items
  • One-click CSV export of weekly sales

AI Usage Disclosure

I used Claude to generate realistic sample product data and to review my Flask routes for common security mistakes, such as unvalidated input. The database design, business logic and interface were written and tested by me.

03

REST API · Java

Project Title: LibraryLink

Library management back-end

Software Used

Java 17Spring BootSpring Data JPASpring Security (JWT)MySQLMavenJUnit 5 & MockitoPostmanSwagger / OpenAPIIntelliJ IDEAGit & GitHub

Project Overview

LibraryLink is a RESTful back-end that manages books, members and loans for a small library. It exposes clean, documented endpoints so that any web or mobile front-end can plug straight into it.

Design Process

  1. Plan. Gathered the requirements, designed the endpoints and wrote the API outline before writing any code.
  2. Model. Created an entity-relationship diagram for books, members and loans and normalised the tables in MySQL.
  3. Build. Implemented the API in Java with Spring Boot and Spring Data JPA, secured it with Spring Security and JWT, and added input validation and consistent error responses.
  4. Test & document. Tested endpoints in Postman, wrote unit tests with JUnit 5 and Mockito, and published interactive documentation with Swagger UI.

Final Outcome

A secure, well-documented API that handles the full borrowing cycle.

  • Endpoints for books, members, loans, borrowing and returns
  • Role-based access for librarians and members
  • Overdue-loan detection
  • Interactive Swagger documentation and consistent JSON errors

AI Usage Disclosure

I used Claude to explain how Spring Security’s JWT filter chain works in plain language and to suggest edge cases for my unit tests. I wrote the entities, services and controllers myself and checked every suggested test before keeping it.
